# Security

This is a public repository. The rules below keep secrets out of it and limit what any single
credential can do.

## Secrets inventory

| Secret                       | Stored in                                                                                   | Grants                                | Rotation                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------ |
| Supabase staging DB password | GitHub environment `staging` (`SUPABASE_DB_PASSWORD`) and the maintainer's password manager | full access to the staging database   | manual; after rotating in Supabase, update the GitHub secret |
| Supabase local keys          | `.env.local` (generated)                                                                    | local Docker database only            | regenerated by `pnpm db:start` + `pnpm env:local`            |
| Vercel OIDC token            | `.env.local` (from `vercel env pull`)                                                       | short-lived access to Vercel services | automatic                                                    |

There are **no long-lived API tokens** in CI. Migrations connect with the database password
through the session pooler, so no Supabase access token is needed
([ADR 0002](adr/0002-migrations-via-direct-connection.md)).

Public by design: `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. They
reach the browser; the data is protected by Row Level Security, not by hiding these values.

## Rules

1. **Never write a secret on the command line.** Run the command without the value and paste it
   when prompted, so it never ends up in shell history or in a command's arguments:
   ```bash
   gh secret set SUPABASE_DB_PASSWORD --env staging --repo utity-tools/ai-driven-kanban
   vercel env add SOME_SECRET preview
   ```
2. **`NEXT_PUBLIC_` only for values meant to be public.** Anything with that prefix is shipped to
   every visitor. Supabase `sb_secret_…` keys must never use it.
3. **Every table has RLS enabled and explicit policies**, in the same migration that creates it.
4. **Least privilege:** grant a token or key only the permissions and projects it needs, with an
   expiry date. Delete credentials that are no longer used.
5. **Only `.env.example` is committed.** `.gitignore` excludes every other `.env*` file.
6. **Production changes need a human:** production migrations wait for manual approval (GitHub
   environment `production`) and production deploys only come from `main`.

## Automated safeguards

- **GitHub secret scanning with push protection:** pushes containing known secret formats are
  rejected.
- **Masked CI logs:** secrets and values derived from them (e.g. the URL-encoded DB password) are
  masked; logs are public in a public repository.
- **Claude Code permissions:** agents cannot read `.env*` files, run `supabase db push` or deploy to
  production (`.claude/settings.json`).
- **Dependabot alerts** for vulnerable dependencies.
- **Vercel Authentication** keeps preview deployments private.

## HTTP security headers

Every route sends these headers, defined in `src/lib/security/headers.ts` and wired in
`next.config.ts` ([ADR 0011](adr/0011-security-headers-and-partial-csp.md)). On rendered pages the
proxy adds a per-request nonce to the CSP ([ADR 0012](adr/0012-nonce-based-script-csp.md)):

| Header                    | Value                                                                       |
| ------------------------- | --------------------------------------------------------------------------- |
| `Content-Security-Policy` | `frame-ancestors 'none'; object-src 'none'; base-uri 'self'; form-action …` |
| (rendered pages)          | `…; script-src 'self' 'nonce-…' 'strict-dynamic'`                           |
| `X-Frame-Options`         | `DENY`                                                                      |
| `X-Content-Type-Options`  | `nosniff`                                                                   |
| `Referrer-Policy`         | `strict-origin-when-cross-origin`                                           |
| `Permissions-Policy`      | `camera=(), microphone=(), geolocation=(), browsing-topics=()`              |

`form-action` allows `'self'`, the Supabase origin and `https://github.com`, because the GitHub
sign-in form redirects through both. Vercel adds `Strict-Transport-Security` in production.
Styles are not restricted (Tailwind, Radix and dnd-kit use inline styles). A new third-party
script must receive the nonce from the `x-nonce` request header, or the CSP blocks it.

## If a secret leaks

1. **Revoke or rotate it at the source first** (Supabase, Vercel, GitHub). Removing it from the
   repo or a log does not make it safe.
2. Replace it where it is used (GitHub environment secret, Vercel env var).
3. Remove every copy: repository, CI logs (delete the run), shell history.
4. If it reached git history, rewriting history is not enough on a public repo: treat it as
   compromised and rotate it anyway.
5. Write a blameless post-mortem in `docs/incidents/`.
